# Corepass

Личный VPN-клиент для Windows на **Rust + Tauri 2** и модуль управления для **OpenWrt**.

## 0.4 preview: свой сервер из приложения

Ветка разработки добавляет раздел **«Мой сервер»**: SSH-доступ к своему VPS, проверку условий установки, установку отдельной службы, создание и отзыв клиентов, персональные ссылки и QR-коды. Это предварительная версия: полный цикл установки на реальном VPS ещё не проверен. Стабильный релиз 0.3.0 остаётся доступен отдельно.

Для первого выпуска мастера нужен **чистый Ubuntu 22.04/24.04 amd64**, вход SSH от root и домен, направленный непосредственно на VPS. Одного IP недостаточно для выбранного сценария с публичным HTTPS-сертификатом. Порты 80 и 443 должны быть свободны.

Мастер сначала получает SSH-отпечаток без отправки пароля. После его подтверждения выполняет проверку без записи; установка требует отдельного нажатия и плана этой проверки. SSH-пароль используется только для текущего действия и не записывается на диск. Для управления клиентами приложение запрашивает его снова. Сохранённые адрес, домен и закреплённый отпечаток находятся в `%LOCALAPPDATA%\CorepassNext\selfhost`.

Управление сервером работает отдельно от локального VPN: открытие страницы и чтение списка сохранённых серверов не подключаются по SSH, а ошибка управления не останавливает туннель. Серверная служба использует отдельные пути `/opt/corepass-server` и `corepass-server.service`; её управление доступно через SSH, дополнительная публичная веб-панель не открывается. Загрузка Caddy Naive закреплена по версии и SHA256.

Существующие Amnezia, S-UI и веб-серверы мастер не переносит автоматически. При занятых портах или неизвестных файлах установка останавливается с объяснением. Для текущего сервера с работающим VPN сначала потребуется отдельный сценарий миграции. Отзыв клиента применяется через перезагрузку собственной конфигурации Caddy; уже открытые соединения могут завершиться позднее, мгновенное принудительное отключение не обещается.

Экспортированная ссылка и QR-код дают доступ к серверу. Они появляются только после явного действия; результаты операций очищаются из памяти контроллера через пять минут. Подробности проверки предварительной версии находятся в [DEVELOPMENT.md](DEVELOPMENT.md).

## Windows

Corepass Next использует официальный sing-box как отдельный процесс. Интерфейс: React + TypeScript, локальная сборка без удалённых страниц и телеметрии.

- Naive HTTPS: импорт ссылки или HTTPS-подписки S-UI.
- Системный прокси, весь компьютер (TUN, нужны права администратора), локальный прокси.
- Проверка реального HTTPS-маршрута перед статусом «Подключено».
- Локальный API, постоянный журнал с ротацией и удалением паролей из сообщений.
- Windows Job Object завершает только свой движок; отдельный процесс восстанавливает собственные настройки прокси при аварии.
- Профили старого Corepass можно **скопировать** кнопкой «Из старого Corepass». Исходные файлы не меняются.
- Corepass 0.2 и Next используют разные папки и порты. Пока старый клиент запущен, подключение Next заблокировано.

Данные Next: `%LOCALAPPDATA%\CorepassNext`. API: `http://127.0.0.1:17871`. Прокси: `127.0.0.1:17872`.

## Роутер OpenWrt

Модуль ориентирован на **Cudy WR3000S v1, OpenWrt 24.10, aarch64_cortex-a53 / mediatek-filogic**.
Устанавливается отключённым. Перед включением нужно добавить подписку и выбрать MAC тестового устройства в LuCI → Службы → Corepass.

Одна команда в SSH-терминале роутера:

```sh
uclient-fetch -q -O /tmp/corepass-install.sh https://raw.githubusercontent.com/orangepony4/corepass/v0.3.0/router/install.sh && sh /tmp/corepass-install.sh
```

Установщик скачивает файлы релиза с GitHub, проверяет SHA256, архитектуру, версию прошивки и свободное место с резервом. Служба устанавливается выключенной. Затем откройте **LuCI → Службы → Corepass**, сохраните персональную JSON-подписку S-UI и выберите MAC одного тестового устройства.

Если работает Steer или другой менеджер маршрутизации, Corepass откажется включаться и перечислит конфликтующие компоненты. Для первого теста остановите соответствующий VPN-раздел в Zapret Manager вручную; его конфигурация сохраняется. Автоматическая совместная маршрутизация со Steer в первый релиз не входит. DoH и AmneziaWG-интерфейсы установщик не перенастраивает.

Образ поддерживает проверку и запуск на ARM64 Linux. **На самом Cudy пока не проверены** скорость, потребление памяти под нагрузкой и совместимость правил конкретной установки. Начинайте с одного устройства, проверьте его внешний IP; затем расширяйте список. Неиспользуемые устройства не должны попадать в MAC-список.

Установка не должна удалять или перенастраивать Zapret Manager, Steer, WARP, AmneziaWG и DNS. Совместимость правил требуется проверить на конкретном устройстве. Реальная производительность зависит от процессора, памяти, провайдера и сервера.

## Сборка Windows

Требуются Node.js 22+, Rust stable MSVC, Microsoft C++ Build Tools с Windows SDK, WebView2.

```powershell
npm ci
python scripts/fetch-engine.py windows
cargo test -p corepass-core
cargo test -p corepass-core --features selfhost
cargo test -p corepass-selfhost
npm run build
npm run tauri build -- --no-bundle
```

Для переносимого каталога используйте `scripts/build-windows.ps1`. В нём должны находиться `Corepass-Next.exe` и каталог `engine/`.

## Локальный API

Токен читается из защищённого файла `api-token` в папке Next. Передавайте его в `Authorization: Bearer …`.
Браузерные запросы с Origin/Sec-Fetch-Site и чужим Host отклоняются. API не принимает команды оболочки, пути к исполняемым файлам и произвольные конфигурации sing-box.

```powershell
$token = (Get-Content "$env:LOCALAPPDATA\CorepassNext\api-token" -Raw).Trim()
Invoke-RestMethod http://127.0.0.1:17871/v1/status -Headers @{Authorization="Bearer $token"}
```

Полная схема: `GET /v1/openapi.json` с токеном. Длительные команды возвращают `operation_id`; результат: `GET /v1/operations/{id}`.

В настольной сборке также доступны `/v1/servers`, `/v1/servers/host-key`, `/v1/servers/inspect`, `/v1/servers/install` и `/v1/servers/clients/{list,create,revoke,export}`. Серверные операции получают идентификатор `srv_…` и не используют блокировку или отмену локального VPN. Пароли передавайте только в теле локального запроса; не включайте их в URL, команды оболочки или журнал.
